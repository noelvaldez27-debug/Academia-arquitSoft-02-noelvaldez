# Decisiones arquitectónicas

| ID | Decisión arquitectónica | Driver relacionado | Justificación | Resultado |
|---|---|---|---|---|
| ADR-001 | Monolito modular | DA01 – Escalabilidad; DA10 – Mantenibilidad | Organizar las funcionalidades en módulos independientes dentro de una misma aplicación, facilitando su mantenimiento y escalamiento. | Módulos de Usuarios, Banco de Preguntas, Rendición de Examen, Resultados, Ranking y Analítica. |
| ADR-002 | Clean Architecture | DA10 – Mantenibilidad | Separar las reglas del negocio de las tecnologías externas para facilitar modificaciones y pruebas. | Capas de Dominio, Aplicación, Presentación e Infraestructura. |
| ADR-003 | Almacenamiento temporal con Redis | DA02 – Rendimiento; DA08 – Persistencia | Almacenar temporalmente las respuestas durante los exámenes para reducir la carga sobre PostgreSQL. | Redis para respuestas activas y PostgreSQL para almacenamiento definitivo. |
| ADR-004 | Procesamiento asíncrono con RabbitMQ | DA02 – Rendimiento; DA07 – Procesamiento asíncrono | Procesar el cálculo de resultados y rankings en segundo plano sin bloquear la plataforma. | Cola RabbitMQ y workers para procesamiento de resultados. |
| ADR-005 | Escalamiento automático con Kubernetes | DA01 – Escalabilidad; DA03 – Disponibilidad; DA06 – Eficiencia de costos | Ajustar automáticamente los recursos durante simulacros masivos y reducirlos en periodos de baja demanda. Es la decisión objetivo para producción; el despliegue académico del Sprint 3 usa una alternativa más económica (ver ADR-013). | Contenedores Docker gestionados mediante Kubernetes en producción. |
| ADR-006 | Enfoque offline-first | DA04 – Resiliencia | Evitar la pérdida de respuestas cuando el postulante tenga problemas de conexión a internet. | Almacenamiento local y sincronización automática de respuestas. |
| ADR-007 | Autenticación y control de acceso por roles | DA05 – Seguridad | Proteger los datos personales y académicos restringiendo el acceso según el tipo de usuario. | Autenticación propia, cifrado y autorización por roles. |
| ADR-008 | Comunicación mediante API REST | DA09 – API REST | Separar la interfaz web de los servicios mediante una comunicación estandarizada. | API REST entre frontend y backend. |
| ADR-009 | Procesamiento de separatas en segundo plano con extracción por tipo de archivo | DA07 – Procesamiento asíncrono; DA10 – Mantenibilidad; DA05 – Seguridad | Leer directamente el texto de los archivos Word y PDF con texto, y usar inteligencia artificial solo para imágenes y PDF escaneados. El procesamiento se hace en segundo plano para no bloquear la plataforma, cada formato tiene su propio extractor para poder agregar formatos sin afectar el resto, y se validan el tipo y el tamaño de los archivos subidos. | Extractores por tipo de archivo, procesamiento mediante RabbitMQ y revisión del docente antes de incorporar las preguntas al banco. La lectura de imágenes se resuelve según ADR-010 y ADR-011. |
| ADR-010 | Servicio de IA detrás de una interfaz, con capa gratuita de Gemini | DA11 – Cambio de proveedor de IA; DA10 – Mantenibilidad | Definir una interfaz ServicioIA en la capa de aplicación y dejar el proveedor concreto como un adaptador de infraestructura, para poder cambiar de proveedor sin modificar los módulos. Se usa una capa gratuita con límites de uso, por costo. | Interfaz ServicioIA, adaptador a Gemini (capa gratuita) y adaptador simulado para pruebas automatizadas y de carga, sin consumir la cuota real. |
| ADR-011 | Lectura de imágenes con modelo multimodal, sin OCR independiente | DA11 – Cambio de proveedor de IA; DA07 – Procesamiento asíncrono | Usar el mismo modelo de IA, que acepta imágenes, para extraer el texto de las separatas escaneadas o fotografiadas, evitando instalar y mantener un servicio de OCR aparte. | Las imágenes y los PDF escaneados se envían al modelo a través de ServicioIA, desde el worker de separatas. |
| ADR-012 | Almacén de archivos detrás de una interfaz | DA12 – Almacenamiento de separatas | Definir una interfaz AlmacenArchivos en la capa de aplicación para guardar las separatas originales, de modo que el almacenamiento pueda cambiar sin modificar los módulos. | Adaptador de disco local para desarrollo y pruebas (Sprint 2) y adaptador de Amazon S3 para el despliegue (Sprint 3). |
| ADR-013 | Despliegue en AWS con una instancia EC2 y docker-compose | DA06 – Eficiencia de costos; DA12 – Almacenamiento de separatas | Desplegar en Amazon Web Services aprovechando los créditos de la cuenta. Una sola instancia con contenedores consume menos crédito que los servicios administrados equivalentes. Los servicios administrados y Kubernetes se mantienen como objetivo de producción. | Instancia EC2 con backend, PostgreSQL, Redis, RabbitMQ y la aplicación web en contenedores; Amazon S3 para las separatas. Objetivo de producción: Amazon RDS, ElastiCache y Amazon MQ. |
| ADR-014 | Aplicación web con React y Tailwind CSS, separada del backend | DA09 – API REST; DA04 – Resiliencia; DA10 – Mantenibilidad | Construir la interfaz como una aplicación independiente que consume la API REST, para poder desarrollarla, probarla y desplegarla por separado, e implementar en ella el guardado local de respuestas. | Carpeta frontend/ en el mismo repositorio, servida mediante un contenedor nginx. |
